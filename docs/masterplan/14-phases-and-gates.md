# 14 Phases and gates

Five gates in order, no calendar dates (D17). Each gate is a demonstration, not a status report: Darya opens staging on his own phone, sends a request, looks up a certificate, logs in as an office editor. The order is fixed because each gate is the packaging of the one before: the frame and shared parts first, then the pages that sell, then the pages that prove, then the second language and the move. Design is in hand for every page, so no gate waits on design; what gates wait on is the directors' replies, and the plan runs on working assumptions until they land (DECISIONS P-rows).

**Working rhythm:** one ticket per session (CLAUDE.md), the Wayfinder map as the list, decisions written on the ticket and in DECISIONS.md. Darya and the engineer work the Task tickets together (admin clicks, DNS, Cloudflare, server sudo). The grilling session on day 1 corrects this plan before any code.
